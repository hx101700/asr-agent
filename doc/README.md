## 文档维护

每份文档服务一个明确的读者和任务。使用文档先说明用户要做的操作，再提供必要参考；Release只介绍该版本的用户可见功能、变化、下载及兼容要求。测试记录、包校验和审查过程保存在开发文档。

保持术语、命令及中英文步骤一致。源码和实际运行证据优先于文档；尚未完成的验证明确标注。截图使用真实界面，配文说明用户可以完成的操作。

写作参考：[Google开发者文档指南](https://developers.google.com/style/highlights)。发布流程参考：[GitHub管理Release](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)。
