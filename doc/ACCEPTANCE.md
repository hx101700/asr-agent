# 测试与验收

> 当前为整体验收计划。S1已运行本机环境/BL合约/归档测试：25项成功、3项媒体测试跳过，详见[S1验证记录](S1_VERIFICATION.md)。下表场景不因相关单元测试通过而自动视为端到端通过。真实转写仍需用户选择音频、确认上传和调用。

## 验收目标

用户从 ZIP 开始，在 Windows 10/11 的 Codex 桌面端完成局部安装；自然语言触发网页；配置、选取一个文件、确认；关闭网页后本地任务继续；Codex 最终给出 JSON 和三种可用文档的位置。仅看到云端 `SUCCEEDED` 不算端到端验收通过。

## 验证方法

### 离线测试

使用合成文件或构造的元数据验证边界；不用真实用户词表/转写内容作为仓库fixture。项目单元测试mock CLI进程及产物，验证启动次数、参数传递、状态和文件。若合约探针需统计HTTP请求，使用BL官方可配置的测试端点/外部测试设施；这不意味着项目新增HTTP客户端，不测BL实现的每个内部细节。大文件上限用模拟stat或稀疏测试文件，不为测试上传巨型文件。

### 官方合约探针

锁定 CLI 发布包后检查 `--help`、参数 schema、实际请求构造和输出协议。禁止用真实本地音频执行未经审查的 `--dry-run`。试验记录写清版本、命令模板、预期/实际结果；真实 token 和业务结果只在忽略目录保留。

### 真实云端验收

用户选择 `data/audio/` 中的单个样本并明确执行后，先做不增强的最小链路，再分别验证用户选择的增强功能、说话人和两种鉴权路径。只做验收所需调用；不为排障自动重跑收费识别。

语音识别质量不以“接口成功”替代。由用户标注一小段代表性人工参考文本和重要术语；如需字符错误率/术语召回率，先约定标点、数字、大小写规范和目标，再计算。当前没有人工参考，不预设或声称准确率。

## 整体验收记录模板

记录测试日期、Windows/Codex/Python/Node/CLI版本、安装目录、案例编号、预期/实际、是否通过、脱敏 task_id/request_id、输出位置、未解决事项。发布文档仅保存去敏后的验证结论，完整音频和云端响应不进入仓库。

## 发布门槛

S1 的局部安装、无失败自动重试、固定模型参数及增强方案必须有证据。S1可以得出某种安装方案不可行并报告原因，但这不代表自动安装功能通过。S5/S6须实际完成自动安装，或由用户明确接受范围调整后重新定义验收。S6 必须在干净环境实际完成；仅在开发机运行过不算 ZIP 安装验收。遗留问题必须明确阻塞/非阻塞，由用户确认验收后再合并 master。
