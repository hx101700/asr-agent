## 关键边界复现与回归

- 使用普通目录布局复现私有运行根与Skill重叠写入；现在构造阶段和后续根解析都拒绝重叠，普通项目内安装仍允许。
- 原生选择Skill根/子目录、默认输出根为Skill、最终JSON或文档位置为Skill时，分别在试写或创建前停止。原始JSON及其他成品按真实状态保留。
- 使用实际Windows目录联接验证解析后的目录边界，不只依靠路径字符串比较。
- 在工作目录放置合成json.py、sysconfig.py，通过真实Python子进程验证-I阻止它们被导入；ensurepip/pip也明确使用隔离参数。
- 热词与上下文从Excel、确认快照到BL参数逐字核对，覆盖引号、换行、反斜杠、Unicode和以--开头的文本。
- 提交、查询或结果处理失败不重复识别；写入记录失败保留当次已知事实。导出故障保留已有目标及其他格式。

## 复测

```powershell
.venv\Scripts\python.exe -B -X utf8 -m unittest discover -s tests -t . -v
.venv\Scripts\python.exe -B -X utf8 -m mypy --config-file mypy.ini
npm run check:web
npm run test:web
npm run build:web
npm run test:browser
```

Python 静态检查依赖位于根目录 `requirements-dev.txt`，安装到开发虚拟环境；前端检查和 Playwright 位于根目录 npm 锁。开发构建需要 Node.js `^20.19.0 || >=22.12.0` 和本机 Edge。运行 Skill 的 Node.js 18.17+ 要求不承担这些开发工具的运行条件。

真实BL合约需要先创建`.runtime/skill-contract-workspace`并用当前Skill入口执行bootstrap，或准备经过核对的同版本本机程序依赖；未安装时对应测试明确跳过。复测只使用合成凭据与数据。

构建使用scripts/build_zip.py。只有清单、内容和实际下载都通过后，才更新[STATUS](STATUS.md)中的发布结果。测试和渲染环境在验证结束后清理。
