## 本轮发现与回归

- 实际 `.xlsx` 的“热词”页可以是图表工作表。原实现随后访问 `max_row` 触发 `AttributeError`；现有解析入口检查真实工作表类型，沿已有字段错误链返回中英文提示。测试还验证 Windows 文件句柄及时释放。
- 损坏的交付记录将 `files` 写为列表时，状态查询原先在调用 `.values()` 时异常。现有读取边界补齐类型判断后返回 `OUTCOME_UNKNOWN`，保留 `JSON_READY`、原始 JSON 和既有云端执行事实。
- DOCX 模板的复杂文字字号有独立继承规则。修复前 Normal 缺少 `w:szCs`，会继承 11 磅；Title 的模板值为 26 磅。回归验证普通文字与复杂文字均为标题 20 磅、正文等样式 10 磅，且保留原文。
- 首次全量回归为 291 项、1 项错误：负向认证测试在服务端提前拒绝后继续发送正文，Windows 返回 `WinError 10053`。测试改为声明正文长度后先等待 403，验证服务在读取正文前拒绝无令牌或跨来源请求。生产 HTTP 代码未改；该项及随后全量 291 项均通过，没有通过捕获并忽略连接异常来放宽断言。

其余回归覆盖输入与增强文本的字符保真、工作目录和 Skill 写入边界、目录联接、隔离 Python 导入、配置确认、执行占用、失败不重试、记录保存失败、三格式生成和重导保留旧目标。

## 复测

在仓库开发环境执行：

```powershell
.venv\Scripts\python.exe -B -X utf8 -m unittest discover -s tests -t . -v
.venv\Scripts\python.exe -B -X utf8 -m mypy --config-file mypy.ini
npm run build:web
npm run test:web
npm run test:browser
```

Python 检查依赖位于 `requirements-dev.txt`，前端检查与 Playwright 位于根 npm 锁。开发构建需要 Node.js `^20.19.0 || >=22.12.0` 和本机 Edge；Skill 运行时要求与开发工具分别管理。

真实 BL 本机合约需要在 `.runtime/skill-contract-workspace` 准备同版本程序依赖；可创建该空目录后，用当前 Skill 入口、该目录作为 `--workspace` 执行 bootstrap。缺失该环境时相关测试明确跳过，不能将跳过计为通过。

独立发行检查使用 `scripts/build_zip.py` 构建候选包，解压到新的空目录。测试驱动应先将解压后的 `scripts` 放到模块搜索路径，令 `tests.support.SKILL_ROOT` 指向同一解压目录，并确认所有 `asr_runtime` 模块确实从该位置加载。
