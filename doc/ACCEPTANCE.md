## 实际问题与修正

用户词表在本机导入后，后端准确返回第3行权重非法、第4行重复词权重冲突。原页面把行号放在顶部Alert，却将焦点滚到只显示通用提示的热词区域；表格现在就地显示行、列与修改原因。原Excel只读使用，未提交或打包。

用户对话中重新打开的是原保存成功页，源码没有返回编辑动作。当前新增撤回未执行配置的入口，旧任务记录为STOPPED/LOCAL_CONFIG_REOPENED，恢复原表单后重新保存产生新编号。独立评审还发现撤回成功但HTTP响应中断的恢复缺口：先用单元测试复现失败，再保留最近一次恢复回执，同一编号可再次取回；真实浏览器注入502验证了该行为。

上下文没有用户提供的已复现故障案例。本轮按阿里云官方字符限制检查空白、长度和不可传输字符，改善定位说明，不推测文本是否与录音语义相关。

## 复现入口

开发依赖与`.runtime/skill-contract-workspace`中的固定BL/pip准备完毕后：

```powershell
.venv\Scripts\python.exe -B -X utf8 -m unittest discover -s tests -t .
.venv\Scripts\python.exe -B -X utf8 -m mypy --config-file mypy.ini
npm run test:web
npm run build:web
npm run test:browser
```

`test:browser`默认使用合成词表，可用`MEMOFLOW_TEST_HOTWORDS`指定经授权的本机错误样表；只读源文件、修改网页副本，并核对源文件摘要。真实用户数据不得纳入测试源码、Git或ZIP。
