# 使用说明

> 当前已有S2本地网页：可直接选文件、组合增强、校验并保存配置，尚不执行云端转写或生成成品。

## 已实现的开发命令

前提：Windows x64、已有Python3.12+和带npm的Node.js18.17+，网络可访问npm官方registry。缺少基础运行时的自动安装尚未实现。

```powershell
python scripts/asr.py bootstrap
.venv\Scripts\python.exe scripts/asr.py doctor
.venv\Scripts\python.exe scripts/asr.py probe-bl
.venv\Scripts\python.exe scripts/asr.py serve
.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -t . -v
```

bootstrap只向项目内创建虚拟环境，安装锁定BL、PyAV和python-dotenv；不改全局PATH或Codex配置。PyAV wheel自带FFmpeg库，无需下载ffmpeg.exe或ffprobe.exe。doctor返回非零表示有缺失项，不能只看JSON是否打印成功。probe-bl仅用虚构URL构造请求，不读取密钥或上传音频。

旧bootstrap-media命令已移除。媒体与配置验证见[S1验证记录](S1_VERIFICATION.md)。

安装后的工具、缓存和状态保存在`.tools/`、`.runtime/`、`.state/`，均不进入Git。未提供真实登录或转写命令，不能从环境检查成功推断账号已可用。

## API Key配置

用户在本地编辑项目根目录`.env`，填写`DASHSCOPE_API_KEY=`右侧的值；不要发到聊天中。发行包首次配置可参考`.env.example`，已有.env不要覆盖。

```powershell
.venv\Scripts\python.exe scripts/asr.py api-key-status
```

此命令只返回是否已配置，不输出密钥、不访问百炼验证权限。网页已有“使用API Key”选择项，后端从.env读取；页面不会显示密钥输入框或编辑.env。真实密钥有效性由正式BL调用判断。选择控制台登录时不读取.env中的Key。

## 适用场景

在 Windows 10/11 的 Codex 桌面端将一个本地录音文件转换为带时间戳的 Excel、Word 和 Markdown，并保留 JSON。每次处理一个文件。固定使用 `qwen-audio-3.0-asr-flash-filetrans`。

## 准备工作

准备百炼账户或普通 API Key、一份受支持的音频；需要热词时准备模板格式的 `.xlsx`。具体音频和词表限制见 [官方能力说明](REFERENCES.md)。不要把密钥粘贴到 Codex 对话或写进源码。

## 当前网页操作

运行serve后浏览器会打开会话链接；也可加--no-browser，让Codex打开终端返回的链接。仅监听本机。页面可直接选择或拖入音频和.xlsx；文件先传给本机服务，不会发送阿里云。即时热词与上下文可同时勾选，地域固定北京。

1. 在“音频文件”中选择或拖入文件，等待显示文件名、大小与“已就绪”；再次点击可更换文件。
2. 在“识别选项”中按需开启即时热词、上下文。说话人默认开启，多声道合并说明会保留在核对信息中。
3. 在“连接与保存”中选择连接方式。保存位置默认使用项目outputs目录，点“修改”展开输入框。
4. 点击底部“检查配置”。通过后自动定位到配置概览，核对声道处理计划、增强和最终目录。可点“返回修改”；更改任何输入都需要重新检查。
5. 出错时查看提示及Excel行号，点“前往问题位置”可定位输入框，折叠的保存位置会自动展开。内容不会被自动截断，失败不会自动重试。
6. 点击“确认并保存配置”后查看回执，可关闭网页并返回Codex。配置保存在.state/jobs/<job_id>/config.json，刷新恢复同一回执。S2确认不授权云端执行；尚不会转换、转写或导出文档。

本机接收音频上限为2,000,000,000字节，Excel为5MiB；临时OSS实际上传仍受1,000,000,000字节的项目阈值约束，多声道副本需在S3生成后复核。当前输出目录仅允许项目outputs及其子目录。热词Excel错误显示具体行，公式不执行，超限不截断。

关闭网页不会关闭本地服务；可在启动它的终端按Ctrl+C。正常退出清理未确认暂存副本，已保存配置引用的文件继续保留。

## 后续完整流程（尚未全部实现）

1. 将发行 ZIP 交给 Codex，指定解压/安装目录。Codex 检查环境并在项目内安装所需组件；超出目录的操作不会被默认接受。
2. 在该项目中说“帮我转写这个录音”。Codex 启动本地网页。
3. 选择控制台登录（推荐）或“使用API Key”。后者要求用户提前填写项目.env，页面仅显示配置状态；控制台登录在阿里云官方页面由用户完成。
4. 直接选择或拖入一个音频，查看格式、大小、时长、声道是否符合要求。
5. 按需独立勾选即时热词和上下文，两者可以同时开启；Excel直接选择/拖入。说话人默认开启，可关闭；多声道且保持开启时，会提示生成单声道副本。
6. 确认 JSON 与文档目录，默认均位于 agent 的 `outputs/<job_id>/` 下。
7. 核对上传范围、识别配置及声道处理提示，点击确认。需要时先生成单声道副本并重新检查，再交给BL上传；原文件保留。程序记录任务后提示可以关闭网页；请保持电脑和本地任务进程运行。
8. Codex 等待并汇报结果。完整成功时提供 JSON、Excel、Word、Markdown 的位置；部分失败时逐项说明已保存和未完成的文件。

## 数据保存说明

- 本地源音频和热词表不会被自动删除。
- 音频仅在确认转写后上传百炼临时 OSS；词汇/上下文会作为识别输入发送到百炼。
- 临时 OSS 依官方规则自动过期；项目不承诺音频完成识别后立即从云端删除。
- 首版采用即时热词，不创建独立云端热词表。
- 本地 JSON 和文档可能包含敏感内容，保存在被 Git 忽略的位置；不会自动发到其他服务。

## 常见问题

### 关闭网页会停止转写吗？

设计目标是确认后的任务独立于页面执行。关闭电脑或结束本地进程可能中断等待和导出，不能与关闭网页混为一谈。该行为须在 S3 实测后才能正式承诺。

### 为什么不能自动重试？

这是项目明确要求。提交超时也可能已经产生云端任务；自动重提交可能造成重复调用。遇到错误先保留已知任务信息，用户可决定恢复查询或重新执行。

### 云端成功但 Word 保存失败怎么办？

先保留 JSON 与已完成文件；修复目录权限、磁盘空间或文件占用问题后，只重新导出失败格式，不再次识别音频。

### 模型允许 2 GB，为什么本工具会拒绝更小的文件？

本版仅使用临时 OSS，其上传限制更严格。最终可接受大小必须满足上传服务和模型两边限制。

### 为什么热词或上下文超限不能直接提交？

某些服务端规则会截断或选取部分输入，可能使增强效果不符合预期。界面会在上传前指出问题，让用户决定如何修改。

### 为什么会提示合并为单声道？

所选模型的说话人分离要求单声道。本工具默认开启说话人区分；检测到待识别音轨包含多个声道时，会在最终确认页说明合并为单声道并上传副本，原文件保持不变。合并后不会保留左右声道区分。关闭说话人选项时，不为此转换声道。

转换后会再次检查实际文件大小、格式、声道和时长。转换失败或副本超限时停止，不自动降低编码质量或关闭说话人。

### 说话人标签代表真实身份吗？

不代表。标签仅区分模型判断的不同声音，可能有错误，不会自动推断姓名。

### 怎么排查错误？

先看失败阶段、原始错误码、中文解释和下一步。官方含义见 [状态与错误说明](ERRORS.md)。提供排障信息时使用脱敏摘要，不提交密钥、签名链接、完整音频或私人转写内容。
