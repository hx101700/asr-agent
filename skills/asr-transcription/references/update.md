# 从 ZIP 更新 Skill

用于用户提供新的 `asr-transcription` ZIP 并明确要求更新已安装副本。更新范围是 Skill 的代码、页面资源和说明；工作目录中的环境、凭据、录音、任务记录和转写文件保持原样。

## 更新前

1. 确认目标是当前实际加载的 Skill 目录，读取其中的 `SKILL.md` 核对名称。沿用这个安装位置，避免新建同名副本。
2. 核对使用该安装副本的任务已结束。读取当前对话持有的执行会话；`login`、`transcribe`、`export` 或安装仍在运行时，先让原进程完成，再继续更新。网页仍在填写时让用户完成或明确放弃编辑后关闭对应 `serve`。只关闭标签页不会结束服务。
3. 其他对话是否还在使用无法确认时，向用户确认这些任务已经结束。磁盘 `RUNNING` 记录不能证明进程仍在运行或已经结束，也不要按进程名称批量终止程序。

新版 `asr.py` 在命令执行期间持有入口文件的只读句柄，Windows 会阻止整体替换其目录。旧版没有这项保护，第一次更新尤其需要核对已启动的任务。该检查不替代任务衔接，也不终止任务或取消云端请求。

已保存但尚未执行的配置可以保留：结束对应 `serve` 后更新，随后重新读取该任务状态。未保存的网页编辑只在会话内，先让用户保存或明确放弃；不能在用户填写期间替换页面资源。

## 执行更新

在安装目录之外解压用户提供的新 ZIP，阅读新版 `SKILL.md` 和本说明。从新包的解压目录运行更新脚本，使用已准备的 CPython 3.12；按执行工具的权限机制取得安装目录写权限。

```powershell
python -S -X utf8 '新ZIP解压目录/scripts/update_skill.py' `
  --zip '用户提供的asr-transcription.zip完整路径' `
  --skill-dir '当前已安装的asr-transcription完整路径' `
  --tasks-finished
```

只有完成上述核对才使用 `--tasks-finished`；它表达调用者已确认任务结束，不是强制终止选项。不要从正在被替换的目录运行更新脚本，ZIP也应留在该目录之外。

脚本先解压并核对包，再在同一磁盘整体替换目录。正在使用或权限不足时保留旧资源并报错；替换失败会恢复原目录。若系统也阻止回滚，错误会给出保留的原副本位置，先处理该实际错误再恢复，不反复尝试或删除原副本。

## 更新后

- `status=updated` 表示资源已替换，重新读取安装位置的 `SKILL.md`。
- `dependencies_changed=false` 时复用原工作目录环境。为 `true` 时，使用新版入口按[运行准备](usage.md#运行准备)执行 `bootstrap`；已有BL目录冲突等问题按实际回执处理，保留原环境和用户数据，不承诺自动迁移所有依赖版本。
- `retained_backup` 非空时，替换已成功但临时旧副本未清理，核对回执中的精确路径后处理；正常成功会自行清理。
- 继续原任务前重新读取它的实际回执。更新本身不执行转写、不重试失败任务，也不改写既有任务协议。版本不支持旧配置时报告实际不兼容，不补写摘要或猜测字段。

当前识别模型为`qwen-audio-3.1-asr-flash-filetrans`。其它模型的已确认配置可以查看，成功结果可以本地重导并保留原模型标注；`transcribe`仅接受当前模型的确认配置，模型不同时会在执行占用前提示重新配置，不改变历史记录。

Codex会自动发现Skill文件变化；如果仍未显示更新，可重新开始对话或重启Codex。[OpenAI官方说明](https://learn.chatgpt.com/docs/build-skills)说明的是技能发现，不能据此假设已运行的Python、Node或网页进程会热更新。
