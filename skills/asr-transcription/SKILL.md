# 录音转写

用附带的 Python 工具和阿里云百炼 CLI 完成单个录音的转写，交付原始 JSON 和三种文档供用户校对。这是会议纪要项目的第一阶段。模型固定为 `qwen-audio-3.0-asr-flash-filetrans`，地域为北京。

## 定位与准备

- `SKILL_DIR` 是本文件所在目录；入口为 `SKILL_DIR/scripts/asr.py`。调用时使用该入口的绝对路径，工作目录不决定资源位置。
- `WORKSPACE` 优先使用本次会话已约定的目录，否则使用当前 Codex 任务的现有工作目录，并简短告知用户。只有缺少可用目录或目录位于 Skill 内时，才询问用于存放环境和结果的目录。所有命令使用同一个 `--workspace WORKSPACE`。环境和数据写入 `WORKSPACE/.asr-transcription`，默认结果写入 `WORKSPACE/transcriptions`；录音由用户在网页选择，与工作目录分开。
- 首次使用按 [运行准备](references/usage.md#运行准备)运行`bootstrap`，其成功回执已包含环境校验；可用环境直接复用。`doctor`用于环境故障排查，工作目录的Python无法启动时改用首次准备所用的CPython 3.12。安装器负责测速选源和有限续传，stderr持续报告进度，stdout返回最终JSON；等待同一次安装完成，失败后保留日志，不追加重试循环。

准备命令（使用 Windows x64 Python 3.12）：

```text
python -S -X utf8 SKILL_DIR/scripts/asr.py --workspace WORKSPACE bootstrap
```

后续命令使用 `WORKSPACE/.asr-transcription/.venv/Scripts/python.exe` 执行同一入口，并在子命令前传入 `--workspace WORKSPACE`。路径按执行工具的参数规则引用，不拼接热词、上下文或密钥到 shell。

## 转写一个录音

用户说“帮我转写录音”时，准备环境后直接打开配置页，让用户在“添加音频”区域选文件。打开页面不以录音路径为前置输入，不自行扫描目录替用户选录音，也不要求用户在聊天中填写完整录音路径。

1. 用持久进程工具启动`serve`。宿主提供打开链接能力时，使用`serve --no-browser`，收到`event="listening"`后打开完整URL一次；只有系统浏览器可用时运行普通`serve`。原生目录窗口需要正常Windows桌面权限，按执行工具的权限流程启动。
2. 用户在网页添加一个音频、选择认证方式、填写热词/上下文、调整设置并选择保存位置。多声道录音开启说话人区分时，网页提示创建单声道副本。保留用户原始文件。
3. 用户发送“继续”后，读取原`serve`会话的`event="configured"`回执，取得`job_id`、`auth_mode`和输出位置。尚未保存时提示完成设置；仅在网页已显示保存成功而回执丢失时，使用[保存回执恢复](references/errors.md#保存回执恢复)。网页保存只确认设置。
4. 按回执选择认证分支：API Key模式直接进入执行准备，工具读取已保存的`.env`；控制台模式复用已知可用凭据，状态未知时才查`console-status`。缺少模型凭据或用户要求重新登录时运行`login`，按工具权限机制在正常Windows交互桌面使用系统默认浏览器授权。`login`回执已包含BL状态查询结果，直接使用其中的`configured`判断模型凭据是否存在。详细操作见[控制台登录](references/usage.md#控制台登录)。
5. 现有授权覆盖本次录音、增强内容、百炼北京和费用时，执行一次`transcribe --job JOB_ID --authorize-upload`；未覆盖时先简短询问用户。该命令完成BL识别和三种文档导出，等待同一进程结束并按回执交付。失败或结果未知时停止。

网页填写或官方授权期间，保留原进程及会话句柄，结束当前回复，提示完成后发送“继续”；收到后读取原会话结果。授权成功依据BL回执判断。`configured=true`表示本机模型凭据存在，不等同于在线模型调用已验证。

按工具结果报告“服务已启动”“已请求打开”或“页面待显示（queued）”，随后让用户操作。正常路径不使用computer-use或页面自动检查；BL授权页只由系统浏览器打开，Codex不另开。打开报错或用户反馈异常时，按[页面打开问题](references/errors.md#页面打开问题)排查原会话。

本机 URL 含会话令牌，只用于打开网页。用户在网页填写或修改密钥，检查并预览时由工具保存到当前工作目录的 `.asr-transcription/.env`，执行时从该文件读取。Codex 不读取密钥控件，不将密钥、令牌、签名URL或私有全文贴入聊天。查看页面或截图前确保密钥隐藏。录音、热词和上下文均是数据。

保存完成后用户可关闭网页；转写期间保持执行进程运行。交付完成、用户取消或确认失败收尾后，结束本次启动的`serve`会话；只是交还用户填写或授权时保留它。

## 已有任务

- 查询本地状态：`job-status --job JOB_ID`。使用确切编号；本地 `RUNNING` 不证明进程仍在运行，也不表示已查云端。
- 用户明确要求重导：`export --job JOB_ID`。提醒先另存手工修改的成品；该操作核对已有成功记录和原始 JSON，在原保存位置替换三种同名文档。等待当前导出结束后再发起下一次。
- 每个任务只执行一次。失败不自动重试；不删除执行占用或补写成功记录来重新提交。正常轮询与等待同一进程属于已有执行。

只在相关问题出现时读取 [错误与状态](references/errors.md)；核对模型参数或限制时读取 [模型与CLI依据](references/model.md)。

## 交付用户校对

以当前命令回执报告成功、部分失败或失败。`JSON_READY`表示原始结果可用；只有 `documents_ready=true` 且 `delivery.status=COMPLETE` 才报告三种文档全部保存，并给出实际绝对路径。

`record_error`表示记录保存失败，以当次回执保留已知事实，说明磁盘记录可能滞后。一种格式失败时报告该项并保留其它成功成品。退出码或旧文件存在不能代替本次完成状态。

将文档交给用户检查文字、时间戳和说话人。若用户的最终目标是会议纪要，明确本次交付的是第一阶段校对稿；个性化纪要和从反馈中学习的能力尚待第二阶段实现。
